# ADR-007: Gateway Rate Resilience, Full-Jitter Backoff, and Headerless Throttle Handling

**Status:** Proposed
**Date:** 2026-09-02
**Version:** 0.1
**Scope:** Platform. Binds every MCP connector repository in the org (`biosciences-mcp`, `biosciences-mcp-edge`, `psychology-mcp`, and future connector repos) per the placement rule in `biosciences-program/docs/adr/README.md`. Repositories record scoped divergences in their own `docs/adr/README.md`.
**Origin:** AGE-592 codified this behaviour on 2026-08-16 as Principle VIII of the [`psychology-mcp` constitution](https://github.com/open-biosciences/psychology-mcp/blob/main/.specify/memory/constitution.md) and cited it as "platform ADR-007". No such document existed; this is that document (AGE-690). Its clauses and measurements are reproduced here in full so that it stands on its own; nothing here is new policy. (`psychology-mcp` was private when v0.1 was drafted and became public on 2026-09-03; links were added then.)

## 1. Context and Problem Statement

Every connector in the platform talks to a public API that throttles. Three things were true on 2026-09-02:

1. **The behaviour existed but was never a platform decision.** ADR-001 lists `RATE_LIMITED` in its error registry (Appendix B) and the Constitution v1.1.0 requires "client-side rate limiting with 10 req/s, exponential backoff, thundering herd prevention", but neither names the constants, the jitter, the `Retry-After` precedence, or what to do when an upstream throttles without publishing any rate signal.
2. **The implementation is duplicated and inconsistent.** `biosciences-mcp`'s `LifeSciencesClient` base (`clients/base.py`, 76 lines) carries no retry logic. Eleven of thirteen clients re-implement it:

   | Client | Retries | Backoff | Jitter | Honors `Retry-After` |
   |---|---|---|---|---|
   | hgnc, uniprot, string, biogrid, ensembl, entrez | 3 | `2**attempt` | none | yes |
   | chembl | 3 | `2**attempt` (SDK executor path) | none | no |
   | drugbank, opentargets | 3 | `BACKOFF_FACTOR**attempt`, capped `MAX_BACKOFF = 60.0` | none | yes |
   | pubchem | 3 | interval-based | 10% additive | no |
   | iuphar | 3 | none (retry without delay) | none | no |
   | wikipathways, clinicaltrials | none | none | none | partial |
   | `biosciences-mcp-edge` biogrid_orcs | none | none (2 req/s lock only) | none | no |
   | `psychology-mcp` [`LiteratureClient`](https://github.com/open-biosciences/psychology-mcp/blob/main/src/psychology_mcp/clients/base.py) | 4 attempts | full-jitter `uniform(0, min(base·2ⁿ, cap))` | full | yes, with RFC 9110 date parsing |

   The "platform constants" that Principle VIII cites (`MAX_RETRIES = 3`, `BACKOFF_FACTOR = 2.0`, `MAX_BACKOFF = 60.0`) exist verbatim in two clients (drugbank, opentargets); the rest agree on the retry count only.
3. **Headerless throttles broke a live suite.** Semantic Scholar (AWS API Gateway) returns 429 with `x-amzn-errortype: TooManyRequestsException` and no `Retry-After` or `x-rate-limit-*`. Measured (AGE-590): the 429s are stochastic, not rate-proportional (8-call sweeps drew 4/8 at 2.5 s spacing, 2/8 at 4.0 s, 4/8 at 6.0 s). A per-test fetch failed on a different random test every run. The obvious remedy, stepping the interval up on every headerless 429, climbs on noise with nothing to relax it.

## 2. Decision

### (a) Discovered where published; declared where not

A connector's rate posture is read at runtime from the upstream's rate headers where they exist (`x-rate-limit-limit` / `x-rate-limit-interval`, `Retry-After`). Where the upstream publishes nothing, the connector MUST declare its interval from measurement and MUST say in code where the number came from. Measured: Crossref's polite-pool limit moved 3 → 10 req/s inside 24 hours, which is why the runtime read is worth having.

### (b) Silence is not permission to speed up, and a throttle is not proof to slow down

Absent rate headers leave the posture unchanged. A headerless 429 MUST NOT ratchet the minimum interval upward on its own. Any adaptive step-up MUST be paired with an explicit decay and MUST be justified against a measurement showing the throttle tracks the rate.

### (c) Retry constants are the platform's, and divergence is named

Full-jitter exponential backoff, `delay = uniform(0, min(base · 2**attempt, cap))`, with `Retry-After` taking precedence where present (seconds or HTTP-date per RFC 9110).

| Constant | Value | Meaning |
|---|---|---|
| `MAX_RETRIES` | 3 | four attempts including the first |
| `BACKOFF_FACTOR` | 2.0 | exponent base |
| `MAX_BACKOFF` | 60.0 s | cap on a single sleep |
| `backoff_base` | connector-specific | the only constant a connector MAY diverge on, and only where the upstream cannot say when to retry; the measurement MUST be recorded |

Retried statuses: 429, 502, 503, 504. Not retried: 4xx other than 429.

### (d) An exhausted throttle is reported, never swallowed

A 429 that survives the retry budget returns the ADR-001 `ErrorEnvelope` with `code: RATE_LIMITED` and `recovery_hint: "Retry with backoff"`. A tool MUST NOT return an empty or partial page indistinguishable from "nothing matched". Where a connector is additive and its loss is a documented degradation, the degradation is permitted, but nothing learned from a call that did not happen may be asserted.

### (e) A live suite minimises calls; it does not merely space them

Live integration suites MUST use module-scoped single-fetch fixtures (fetch once, assert many) and MUST skip on retry-budget exhaustion narrowed to 429 alone, so every other status still fails loudly.

### (f) One implementation per repository

The behaviour in (a) through (d) lives in the repository's base client, not in each connector. `biosciences-mcp` consolidates the eleven copies into `LifeSciencesClient`; `biosciences-mcp-edge` adopts the same base or a verbatim copy of it, as it already does for the §8 envelopes.

## 3. Consequences

**Positive**
- One place to fix; the wikipathways, clinicaltrials, iuphar, and edge gaps close by inheritance.
- Live suites stop being red at random and green by accident.
- `psychology-mcp` Principle VIII gains the platform document it cites.

**Negative**
- A consolidation change touches every client in `biosciences-mcp`; it needs the contract tier (`tests/contract/`) plus a unit test that drives a mocked 429/`Retry-After`/headerless sequence through the base client.
- Full jitter makes exact-timing assertions impossible; existing tests that assert `elapsed >= n` need re-basing on attempt counts.

**Neutral**
- The 10 req/s figure in the Constitution's Required Patterns becomes a default, not a mandate; per-upstream intervals are declared or discovered per (a).

## 4. Implementation Standard (for the accepting change, not this ADR)

1. `biosciences_mcp/clients/base.py`: `_rate_limited_get(path, params)` implementing (a) through (d), with the constants as class attributes and `backoff_base` as a constructor argument.
2. Remove the per-client `_rate_limited_get` and `MAX_RETRIES` copies; keep chembl's executor-path retry but source its constants from the base.
3. Unit test: mocked transport returning 429 with `Retry-After: 2`, then 429 headerless, then 200; assert three calls, that the first sleep honours `Retry-After`, that the second is within `[0, min(base·2, cap)]`, and that a fourth 429 yields `RATE_LIMITED`.
4. `biosciences-mcp-edge`: adopt the base; record the adoption in its `docs/adr/README.md` together with its ADR-001 §3 divergence.
5. `psychology-mcp`: Principle VIII cites this file's path (done 2026-09-03, constitution v1.6.1); its `backoff_base = 2.5` Semantic Scholar divergence is recorded in [its ADR index](https://github.com/open-biosciences/psychology-mcp/blob/main/docs/adr/README.md), adaptation 5.
6. Constitution v1.2.0: point the "Client-side Rate Limiting" Required Pattern at this ADR and at the unit test in item 3 as its enforcement.

## 5. Alternatives Considered

- **Leave it in each client.** Rejected: thirteen implementations already disagree on jitter, `Retry-After`, and retry-at-all.
- **Adaptive step-up on headerless 429.** Rejected on measurement (AGE-590): the throttle is stochastic; a step-up without decay converges on the slowest observed interval.
- **Constitution-only, no ADR.** Rejected: the Constitution names enforcement it does not run; the ADR gives the base-client test something to cite.
