# ADR-008: Transport-Layer OpenTelemetry and OTLP Instrumentation for MCP Tool Execution

- **Status**: Accepted
- **Date**: 2026-09-24
- **Decision Makers**: Don Branson (Platform Architect, Program Director)
- **Consulted**: `lila-graph/hci-canon-evals` Telemetry Architecture, FastMCP Runtime
- **Supersedes**: N/A (Builds directly upon ADR-001 §8 Envelopes and ADR-007 Rate Limiting & Backoff)

---

## 1. Context

Model Context Protocol (MCP) servers act as the boundary between autonomous agent orchestrators (Claude Code, LangGraph, Temporal, AutoGen) and upstream scientific databases (ChEMBL, OpenTargets, HGNC, UniProt, ClinicalTrials).

### The Problem: Opaque Failures at the Transport Boundary
Current agent telemetry frameworks (e.g. LangSmith, Arize Phoenix) primarily instrument the model layer: prompt inputs, completions, and declared tool-use tokens. When an agent tool call fails, execution logs frequently report generic tool errors (`ToolExecutionError` or empty results) without transport context. 

In production, tool failures rarely originate in model hallucination; they originate at the **OpenAPI / HTTP transport layer**:
1. Upstream rate limiting (HTTP 429) exhausting client-side retry budgets (ADR-007).
2. Gateway timeouts (HTTP 504) or dropped TCP connections from public bioinformatics endpoints.
3. Payload truncation or schema divergence on large responses.
4. Latency spikes in multi-hop entity resolution (e.g., Gene Symbol -> Ensembl ID -> ChEMBL Target -> Bioactivity Array).

Without transport-level telemetry, agent platforms cannot determine whether a tool failed due to invalid arguments, an exhausted rate limit, or upstream infrastructure downtime.

---

## 2. Decision

We establish transport-layer OpenTelemetry (OTel) instrumentation embedded directly within `biosciences-mcp` base clients and tool runtimes.

    subgraph Agent Runtime
        A["Agent Platform<br/>(Claude Code / LangGraph / Temporal)"]

    subgraph FastMCP Server Boundary
        B["FastMCP Tool Handler<br/>Span: mcp.tool_call"]

    end

    A -->|"1. Call Tool (JSON-RPC)"| B
    B -->|"2. Invoke Client"| C
    C -->|"3. Propagate Span"| D
    D -->|"4. HTTP GET"| F
    B -.->|"Async Export"| E
    C -.->|"Async Export"| E

### (a) Dual-Span Hierarchy
Every tool execution produces a deterministic two-tier span hierarchy:
1. **Parent Span (`mcp.tool_call`):** Captures high-level tool execution, parsed Pydantic input arguments, runtime status, and return envelope metadata (ADR-001).
2. **Child Span(s) (`mcp.client.http_request`):** Emitted by `LifeSciencesClient._rate_limited_get` for *every* outbound network attempt, recording retry cycles and transport health.

### (b) W3C Trace Context Propagation
Incoming MCP request metadata is scanned for standard W3C `traceparent` strings. 
- If present, tool execution inherits the caller's distributed trace context.
- If absent, the FastMCP server initiates a new root trace.
- All outbound HTTP requests generated by `LifeSciencesClient` inject the active `traceparent` header into upstream requests.

### (c) Standard Semantic Attributes
Span attributes adhere to OpenTelemetry Semantic Conventions:

| Attribute | Type | Example | Description |
| :--- | :--- | :--- | :--- |
| `mcp.server.name` | string | `chembl`, `opentargets` | Target FastMCP server slug |
| `mcp.tool.name` | string | `chembl_search_compounds` | Exact tool identifier |
| `http.request.method` | string | `GET` | Outbound HTTP verb |
| `http.url` | string | `https://www.ebi.ac.uk/...` | Sanitized upstream target URL |
| `http.response.status_code` | int | `200`, `429`, `504` | Upstream HTTP response status |
| `http.retry_attempt` | int | `0`, `1`, `2` | Attempt count under ADR-007 backoff |
| `http.response_content_length`| int | `45230` | Response body byte size |
| `error.type` | string | `RATE_LIMITED`, `TIMEOUT` | Standardized error classification |

### (d) Zero-Cost Offline Invariant (Graceful Degradation)
Telemetry instrumentation MUST NOT break local offline operations or impose mandatory Docker services:
- When `OTEL_EXPORTER_OTLP_ENDPOINT` is unset, the runtime binds a non-blocking `NoOpTracerProvider`.
- Automated test suites run with `InMemorySpanExporter` (zero network I/O, deterministic assertions).
- Production deployments export via OTLP/HTTP to `http://localhost:4318/v1/traces` (compatible with the Jaeger/OTel stack configured in `lila-graph-evals`).

## 3. Consequences

### Positive
- **Deterministic Root-Cause Analysis:** Failures from external rate limits (429) or upstream downtime (503/504) are immediately distinguishable from tool schema errors.
- **Platform Agnostic:** Works identically regardless of whether the agent caller is Claude Code, an OpenAI swarm, Cursor, or a Temporal activity.
- **Direct Metric Verification:** ADR-007 backoff jitter, retry intervals, and `Retry-After` header adherence become empirically measurable via trace span durations.

### Negative
- Adds `opentelemetry-api` and `opentelemetry-sdk` dependencies to `pyproject.toml`.
- Sub-millisecond latency overhead for span creation (mitigated by batch/async OTLP export).

### Neutral
- Offline unit tests remain green without running external telemetry daemons.

---

## 4. Implementation Standard

1. **`biosciences_mcp/telemetry/tracer.py`**:
   - Provide `get_tracer(server_name: str)` returning a tracer configured from environment (`OTEL_EXPORTER_OTLP_ENDPOINT`).
   - Provide a `@trace_tool` decorator for FastMCP tool functions.
2. **`biosciences_mcp/clients/base.py`**:
   - Integrate span wrapping into `LifeSciencesClient._rate_limited_get`.
   - Record `http.retry_attempt` and backoff sleep duration on every retry loop.
3. **Trace Verification Fixture (`tests/telemetry/test_trace_contract.py`)**:
   - Adopt `trace_verifier.py` pattern from `lila-graph/hci-canon-evals`:
   - Execute a mock tool call with a simulated 429 backoff sequence; assert that child spans are emitted with matching trace IDs, correct retry attribute values, and `RATE_LIMITED` error status.

---

## 5. Alternatives Considered

- **Caller-side agent tracing only (e.g. Phoenix/LangSmith only):** Rejected. Blind to HTTP transport status, rate limits, and network retries inside MCP subprocesses.
- **Logging to stderr only:** Rejected. Unstructured text logs cannot be queried, correlated across distributed services, or programmatically verified by automated evaluation suites.
