# Spec Kit process record — biosciences-mcp

**Purpose.** Which `/speckit.*` commands were actually run for each feature, with the artifact each produced and the date it was created. This is a record of what happened, not of what the process document says should happen (`docs/speckit-standard-prompt-v2.md`). AGE-699.

**How dates were established.** The reference repository's git history (`donbr/lifesciences-research`) was squashed to a single initial commit on 2026-01-07 (`4308911`), and this repository received the artifacts in one move on 2026-03-03 (`5278c4e`). Per-artifact dates below therefore come from the `**Created**` / `**Date**` fields in the artifact headers and from Linear issue timestamps, not from git. Where a header names the command that produced the file, that name is recorded; where a file exists with no such marker, the command is **inferred** from the artifact type and marked so.

**Rule going forward.** Every `/speckit.*` run for a feature appends a row to the table below in the same commit as the artifact it produces (see `docs/speckit-standard-prompt-v2.md`, Step 3).

## Discrepancies worth knowing

1. **"analyze" in Linear meant agent audits, not the command.** AGE-118 is titled as a `/speckit.analyze` run and marked Done, but its outputs are agent-written compliance reports. Only 001 has an `analysis.md`, and that file was produced by `/speckit.implement`, not `/speckit.analyze`.
2. **`tasks.md` completion marks are unreliable.** Eleven of thirteen `tasks.md` files are undated, and AGE-118 found 437 completed tasks unmarked. Do not read `[ ]` in a tasks file as "not done".
3. **The checklist files were not produced by `/speckit.checklist`.** Their headers say `clarify`, `plan`, or `tasks`. Requirement-quality checklists in the current Spec Kit sense have never been generated here.
4. **The process document is a template, not a log.** `docs/speckit-standard-prompt-v2.md` records the intended sequence and the prompts used; it does not record runs. The 2026-09-02 DepMap work in the reference repository (AGE-681) showed why that matters: the issue described specify-first, the branch history showed code-first.
