# Spec Kit process record — biosciences-mcp

**Purpose.** Which Spec Kit commands (`/speckit.*` in the January 2026 install; `/speckit-*` from v1.0.4 on) were actually run for each feature, with the artifact each produced and the date it was created. This is a record of what happened, not of what the process document says should happen (`docs/speckit-standard-prompt-v2.md`). AGE-699.

**The process is documented.** `docs/speckit-standard-prompt-v2.md` is the record of the process used for all thirteen servers: its Workflow section fixes the sequence (Step 1 `/scaffold-fastmcp`, Step 2 the standard `/speckit.specify` prompt, Step 3 `/speckit.clarify` → `/speckit.plan` → `/speckit.tasks` → `/speckit.analyze` → `/speckit.implement`), its Server Specification Inventory holds the exact specify prompt used per server, and its version history dates each server's addition (1.0.0 on 2025-12-22 after HGNC; 1.2.0 on 2025-12-23 for STRING and BioGRID; 1.3.0 on 2025-12-24 for Ensembl, Entrez, PubChem, IUPHAR; 1.5.0 on 2026-01-03 for WikiPathways and ClinicalTrials). The artifact set in each `specs/NNN-*/` directory is that workflow's output.

**How dates were established.** The reference repository's git history (`donbr/lifesciences-research`) was squashed to a single initial commit on 2026-01-07 (`4308911`), and this repository received the artifacts in one move on 2026-03-03 (`5278c4e`). Per-artifact dates below come from the `**Created**` / `**Date**` fields in the artifact headers and from Linear issue timestamps. Where a header also names the command that produced the file, that name is shown.

**Rule going forward.** Every Spec Kit command run for a feature, whatever the installed version names it, appends a row to the table below in the PR that carries the artifact it produces (see `docs/speckit-standard-prompt-v2.md`, Step 3). Historical rows keep the dotted names that were current when they ran.

## Discrepancies worth knowing

1. **"analyze" in Linear meant agent audits, not the command.** AGE-118 is titled as a `/speckit.analyze` run and marked Done, but its outputs are agent-written compliance reports. The only `/speckit.analyze` artifact in the repository is 001's `analysis.md` (2025-12-21); no other feature has one, and none was produced by AGE-118.
2. **`tasks.md` completion marks are unreliable.** Nine of thirteen `tasks.md` files are undated (003, 004, 005 and 010 carry a date), and AGE-118 found 437 completed tasks unmarked. Do not read `[ ]` in a tasks file as "not done".
3. **The checklist files were not produced by `/speckit.checklist`.** None names a producer; each names `clarify`, `plan`, or `tasks` as the next step in its closing line, and the content matches the clarify-era requirements checklist. Requirement-quality checklists in the current Spec Kit sense have never been generated here.
4. **The process document records the process, not individual runs.** `docs/speckit-standard-prompt-v2.md` is the authoritative record of the sequence and the prompts used for the thirteen servers; what it cannot show is a deviation on a later feature. The 2026-09-02 DepMap work in the reference repository (AGE-681) is the case: the issue described the documented sequence, the branch history showed code-first. This file exists to catch that, one row per run.
