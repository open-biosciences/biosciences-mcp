## 4. Was checklist or converge used, and would they have helped?

- **`/speckit-converge`: used once** (T048, after core implement, before US2), with a correct record (`docs/speckit-process-record.md:74`). A second run before T026 would have reported Converged. Converge assesses code against the artifacts and runs no tests (template "Goal"), and the artifacts had already narrowed the regression scope (F4, F9). **Verdict: necessary but not sufficient.** Keep it, but don't expect it to catch requirement-scope errors.
- **`/speckit-checklist`: not used** (F10). A run focused on `release-readiness` / `deploy`, after `/speckit-tasks`, would have asked requirement-quality questions such as:
  - "Does SC-002 enumerate every existing test tier, and the tracking issue's acceptance tiers?"
  - "Is the hosting platform's deploy trigger and dependency resolution specified?"
  - "Is rollback defined as restore or re-resolve?"
  - "Who may record the Go/No-Go?"
  Because `/speckit-implement` halts on unchecked checklist items (`.claude/skills/speckit-implement/SKILL.md:85-89`), those gaps would have blocked implementation until resolved. **Inference:** this would probably have caught F4, F5, F7, and F14. F3 is the exception, because it needs data outside the repository.
- **`/speckit-clarify`: skipped**, with three defaults (`docs/speckit-process-record.md:66`). One of them, SC-005, became the T025 waiver.
